## 0. 总体数据流

```
A_data/output/panel_base.parquet          （月频基金面板：因子、市态、nav）
        │
        ▼
C_positions/scripts/1_generate_holdings.py （条件选基：横截面筛选 + 排名 + 定权重）
        │  读 C_positions/config/selection_registry.py 中的策略定义
        ▼
C_positions/output/{strategy_id}_holdings.parquet   （持仓名单表）
        │
        ▼
E_backtesting/scripts/backtesting.py       （总控 CLI）
        ├── engine.py    逐期状态机：漂移 → 调仓 → 换手/费用 → 区间收益
        ├── nav.py       月频多腿净值重建 + 一致性校验
        ├── metrics.py   纯指标函数库
        └── summary.py   按年 + 全区间绩效表
        │
        ▼
E_backtesting/output/{pass_count}_{mwXX.XX}_{strategy_id}/
        ├── {strategy_id}_summary.xlsx     （screening + 各轨道 + 均值 + 标准差）
        ├── {strategy_id}_combo_nav.png
        ├── {strategy_id}_combo_nav_ratio.png
        └── track_{k}_nav(.png / _ratio.png)
```

与原项目的对应关系：`C_positions` 仍负责"信号/持仓生成"，`E_backtesting` 仍负责"执行、净值、绩效"，二者只通过 holdings 文件解耦。

## 1. 全局约定

| 约定 | 取值 | 说明 |
|---|---|---|
| 数据频率 | 月频 | panel_base 的 `month_date`（月末）；净值重建也是月频，原 nav.py 的"逐日滚动"降为"逐月滚动"，一致性校验机制保留 |
| 收益类型 | simple | `Config.PANEL_RETURN_TYPE = "simple"`；returns.py 照搬，仅作口径保险 |
| 调仓时点 | 月末收盘 | t 期用"t 及之前可得"的信息选基，持有 (t, t+h] 区间，不回看未来 |
| 持有期 h | 可配置，默认 6 个月 | 对应研究主 Y `future_ret_6m` |
| 多轨机制 | 轨道数 = h | 照搬原项目五轨思想：track_id = 起始月序号 mod h，h 条错开轨道各自独立回测，组合净值 = 各轨道算术平均。h=1 时退化为单轨 |
| 年化基准 | annual_periods = 12（月） | 原 metrics 的 `holding_days / ANNUAL_TRADING_DAYS` 改为 `holding_months / 12`，函数结构不变 |
| 基准组合 | 当期基金池等权 | "基金池"= 通过同样样本过滤（`is_sample` 等）但不施加选基条件的全体基金；每个调仓日随策略同步再平衡。不再需要外部 benchmark 持仓文件 |
| 费用 | 申购费率 / 赎回费率分开配置 | `cost_rate = buy_turnover * fee_buy + sell_turnover * fee_sell`；默认值在 Config 中给占位（暂定 0，正式数值由使用者定）。`charge_initial_trade` 开关保留 |
| 样本窗口 | ins / oos / all / custom | 照搬 `G_engine/sample_window.py`；INS 截止日沿用 `Config.PANEL_INSAMPLE_END_DATE = 2022-12-31` |

## 2. C_positions：持仓名单契约

### 2.1 输出文件 `C_positions/output/{strategy_id}_holdings.parquet`

一行 = 一个调仓日 × 一条轨道 × 一只入选基金（长表）：

| 列 | 类型 | 说明 |
|---|---|---|
| `rebalance_date` | datetime | 月末调仓日（= panel 的 month_date） |
| `track_id` | int | 0..h-1 |
| `ifind_code` | str | 入选基金 |
| `weight` | float | 目标权重；同一 (rebalance_date, track_id) 内 sum = 1，容差 1e-10 |
| `selection_score` | float | 诊断用：入选时的排序分（如 FAC 值） |
| `n_pool` | int | 诊断用：该调仓日通过池过滤的基金总数 |
| `condition_state` | float | 诊断用：该调仓日的市态取值（1/-1/NaN） |

约定：
- 某调仓日若条件不满足（如市态 NaN、池内可选基金数 < 下限），该 (date, track) **不出现在表中** → 引擎解释为"本期无新信号，维持上期持仓漂移"（对应原 engine 的 `signal_update_flag = 0` 分支）。
- 每条轨道只在自己的调仓月出现行（如 h=6、track_id=2，只在第 2, 8, 14, ... 个月出现）。

### 2.2 策略定义 `C_positions/config/selection_registry.py`

仿 `D_analysis/config/regression_registry.py` 的注册表模式，`strategy_id → dict`：

```python
SELECTION_REGISTRY = {
    "SEL001_hs300up_facm6n6_top20": {
        "pool_filters": {"is_sample": True},          # 池过滤（panel 布尔列）
        "condition": {"state_col": "mkt_state_hs300",  # 市态条件；None 表示无条件
                      "state_value": 1},
        "sort_col": "FAC_rank_vol_m6_n6_pairwise1",    # 横截面排序列
        "ascending": False,                             # False = 取值大的
        "select": {"mode": "top_n", "n": 20},          # 或 {"mode": "top_frac", "frac": 0.2}
        "weight_method": "equal",                       # v1 只做 equal
        "holding_months": 6,
        "min_pool_size": 50,                            # 池太小则本期不发信号
    },
}
```

生成脚本 `C_positions/scripts/1_generate_holdings.py`：
- CLI：`--strategy-id`（必选，可多个）、`--panel-path`（默认 A_data/output/panel_base.parquet）。
- 职责：逐调仓日做池过滤 → 判断市态条件 → 排序取前 N → 定权重 → 落盘 holdings + 一份 `{strategy_id}_holdings_summary.json`（各期入选数、跳过期数及原因）。
- 只用 t 期已知列，禁止触碰 `future_ret_*`。

删除的原逻辑：`signal_ls` 多空方向、`period_ret_ls`、benchmark_ref_row 引用机制。

缺失净值处理（防御规则，v1）：
- 入选基金在区间内 nav 断档 → 该腿自最后可得月起按现金（收益 0）处理，并在结果表 `missing_nav_funds` 诊断列记名；同一基金出现即在运行末尾打印警告汇总。
- 选基时点 nav 缺失的基金不允许入选（在 C_positions 层拦截）。

基准：不再单写引擎变体。基准本身就是"每个调仓日的池等权持仓名单"，由 backtesting.py 内部生成一份 benchmark holdings（同轨道结构），复用同一个 `run_single_track_backtest`。这是对原项目"benchmark 单独一套函数"的简化。

### 3.6 backtesting.py（骨架照搬）

CLI：

```
--holdings-file   C_positions/output/xxx_holdings.parquet（必选）
--panel-path      默认 A_data/output/panel_base.parquet
--sample          all/ins/oos/custom，默认 all
--start-date / --end-date
--fee-buy / --fee-sell   不传则读 Config
```

流程（与原 main() 一一对应）：
1. 读 holdings + panel，校验（权重和=1、日期在 panel 内、基金在 panel 内、无 future 列泄漏）。
2. 从 panel 的 nav 列透视出 `fund_monthly_ret_df`（宽表），并预计算每轨道每区间的 `fund_period_ret_df`。
3. 生成 benchmark holdings（池等权，轨道结构与策略一致）。
4. 逐轨道跑 strategy 与 benchmark → 两组 period_df，行数/索引/轨道结构 assert 对齐（照搬原三条 assert）。
5. nav 重建 → 轨道 NAV + combo NAV（轨道平均）。
6. summary → 逐轨表 + avg + std。
7. screening（§3.7）→ `result_prefix = {pass_count}_{mwXX.XX}_{strategy_id}`。
8. 落盘：summary.xlsx（screening / summary 两个 sheet，排版函数照搬）、combo_nav.png、combo_nav_ratio.png、track 图、可选中间 parquet（默认注释掉，同原项目）。

## 4. 已确认的默认值（2026-07-05 与使用者确认）

1. **持有期与轨道**：h=6，先只跑单轨（track_id=0，每 6 个月调仓一次）；多轨接口保留，跑通后再开。
2. **选基规模**：top_n=20；min_pool_size=200（保证 top20 不超过截面前 10%，回测起点自然落在 2013 年前后）。top_frac=10% 留作后续稳健性检验。
3. **费率**：BT_FEE_BUY = BT_FEE_SELL = 0.0，Config 中必须注明"临时占位，未反映真实申赎费用，绩效为免费用口径，正式费率待定后需重跑"。
4. **基准**：池等权。
5. **screening**：七条按 v1 草案（§3.7），仅作输出标签用，不过滤结果。
